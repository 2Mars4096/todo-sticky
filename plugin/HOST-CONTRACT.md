# Host API: diane-plugin/1

The host resolves `@diane/plugin-sdk` modules: client, records, http, host-context, input-context, panel-context, input, desktop and workflow. The UI package uses host React; no separate agent runtime or login is embedded. CSS accompanies the module. Backend compatibility release requires the shared owner-scoped record service and Universal Cell gateway. Permissions in the manifest request access; they do not grant access.

The product source is maintained in this repository's `plugin/` directory. `RECOVERY.json` records the initial recovery from the shipped packages; new candidates require an explicit pinned-host integration. Standalone apps retain their existing backend and release path.

Task execution uses only the existing projects, preparation, workflows, run, review, open and stop APIs. A run creates a session without automatically navigating away. A review is bound to its exact result version. The backend's inline prior-attempt records may supply read-only session links; they are not a complete history listing. Manual project choices remain device-local until the host supplies a shared binding API. Accepting a result is distinct from integrating Git changes; this package declares no Merge operation.

UI 0.1.8 consumes optional `Workflow.review_conflict` as the current task/step mismatch explanation. It blocks accept/revise without weakening result-version checks. **Discard result** is available only when `Workflow.can_discard_result === true`. It sends the existing review `stop` decision, which the paired host implements as workflow-only dismissal preserving the task's current text, status and steps. Older hosts show an update explanation instead of calling their task-stop operation under a discard label. Failed/stopped workflows expose **Run again** directly for unfinished tasks; closed tasks remain closed. A lost review response retries the same result version and request ID within the current view.

Preparation refresh: POST `/api/sticky-todo/preparations/refresh` with `{scope: pluginScope()}` returns `{queued,scope}`. The scope is the opaque current connection binding, not a filesystem path. Refresh may prepare canonical unfinished tasks but must not dispatch execution. The server rejects a mismatched scope and deduplicates unchanged content. Missing/failed refresh is quiet in the overview; the selected-task host control owns actionable status.

## Optional task editor portal

`TodoPort` accepts `taskEditor?: ComponentType<TodoTaskEditorProps>`. The exported props are `{scope: string, taskId: string, content: string, readOnly: boolean, onChange(content: string): void}`. `taskId` is the canonical `recordId ?? id`, never a row index. The host edits only Markdown text. Todo owns status, actions, reorder, workflow/session links, revision guards and writes. Historical/disabled rows are read-only. Omission preserves the existing editor. Host engine drafts must be keyed by both scope and taskId. The bridge rejects stale account/record/text callbacks and blank task text. No KB file path or independent task runtime is exposed.

## Full-document capability (UI0.1.11/backend0.1.6)
`TodoPort` optionally accepts `documentHost`, `documentEditor` and `documentReview`; exported types are in `TodoDocument.tsx`. Editor receives full source, scope-bound documentId, readOnly/onChange and optional product-owned renderBlockActions(markdown). Review receives before/after/onAccept/onReject; accepting authorizes only the reviewed reconciliation, never execution. Host `createTodoDocumentReview` adapts the shared DocumentChangeReview/createDocumentReview/applyReviewDecision contracts without copying their implementations.

Document host methods: list, read(path), preview(write), save(write), recover(path,document), reviewAgain({path,document,revision}). Write is `{path,document,content,revision,expected}`. `document` hashes owner binding + absolute configured path; `revision` is the exact file SHA-256; `expected` is the canonical task snapshot fingerprint. Read returns source/normalized source, task spans, projection and pending recovery status. Preview assigns missing IDs and reports created/removed IDs, source→canonical links and an existing-task canonical text/status patch. Duplicate IDs/repeated dates block. Cross-document moves block; within-document moves retain canonical IDs.

Local routes: `/api/plugins/todo-documents` GET, plus POST `/read`, `/preview`, `/save`, `/recover`, `/review-again`. Require explicit DIANE_TODO_KB_ROOT and DIANE_TODO_KB_OWNER equal to `/api/plugins/connection` scope. Hosted product routes `/api/plugins/todo/documents/preview` and `/commit` use the existing owner dependency. Deploy the backend wheel to both participating Python runtimes before enabling the capability. Old backend absence is local/unsupported, not a core-startup dependency.

Save journals the exact operation, preserves previous file bytes through note_files, writes the file conditionally, then commits records. A stale canonical token leaves pending recovery. Retry reuses the operation; Review again retains the journal in a `.retained-*.json` safety copy and allows fresh explicit reconciliation. These are sequential recoverable writes, not a cross-system transaction. No background dispatch, title matching or document regeneration is permitted.

UI0.1.12 review callback `onAccept(content?: string)` returns the selectively accepted document. Mixed decisions return to preview with the edited draft, so identity normalization and canonical conflicts are rechecked before save. Rejecting one chunk leaves other chunks pending; Reject all dismisses the proposal.
