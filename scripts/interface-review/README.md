# Dockit review fixtures

These scripts exercise local product UI using a synthetic notebook. Run from the Dockit checkout. Browser work needs Python Playwright and local Chromium. Node builds use the checkout’s installed dependencies. Phone workflows use the Flutter SDK recorded by the project, Xcode for iOS, and Android build tools for APK verification.

1. Run `node scripts/interface-review/source.cjs`. Each source row includes a file span, page owner, locale, stored text, build reference and five individual results.
2. Build local standalone and plugin assets. Run `node scripts/interface-review/build-embedded.cjs` and `node scripts/interface-review/build-components.cjs`. Use `python3 scripts/interface-review/browser.py web-wide web-compact mac-shared embedded signin`. Run `account.py` and `projects.py` separately from this directory. They intercept all external requests with synthetic responses.
3. For Flutter host coverage, set `DOCKIT_REVIEW_DIR` to a fresh evidence folder and run `flutter test test/review_element_matrix.dart`. Set `DOCKIT_COUNTER_REVIEW_DIR` when running `test/archive_count_locale_test.dart` to persist the singular/plural observations.
4. `android.py` requires `DOCKIT_TEST_SERIAL` belonging to a disposable emulator. `native_mac.py` builds a separately identified Tauri app on external scratch storage; it validates the synthetic KB before enabling snapshots. The native iOS flow is `prepare-ios.rb`, a dedicated simulator, `DockitElements.swift` and `export-ios-results.py`. `prepare-simulator.py` and `run-simulator.py` capture deeper screens using real iOS Flutter rendering. `check-cantonese.py <authorized-simulator-uuid>` pins the exact exported app, checks distinct script-specific prompts and leaves the shared device running.
5. Run `reconcile.py` with the profile names shown in `state-coverage.csv`, then `publish.py` and `report.py`. `source-five.jsonl.gz` and `rendered-five.jsonl.gz` are newline-delimited JSON. `source-render-links.jsonl.gz` preserves source positions even when no matching rendered text was captured. Source text matches are clues to coverage and do not uniquely identify a call site.

Native fixtures use explicit local paths and must be pointed at isolated data. Build receipts preserve the identities and SHA-256 digests of the tested artifacts. Keep exploratory data and stored user files outside the fixtures.
